## Purpose

이 문서는 `EVS-009`~`EVS-011`을 실제 stack-bound analysis, static memory map, strict-warning default-gate decision으로 채울 때 필요한 실행 절차를 고정한다.

목표는 V&V v1.4 Finding 4 and 6 follow-up을 template가 아니라 traceable artifact로 전환하는 것이다.

## Scope Boundary

This runbook does not close `EVS-009`~`EVS-011` by itself.

Closure requires actual generated artifacts or a reviewed CI/release policy decision. If only this runbook exists, all three items remain `Open`.

## Preconditions

다음 중 최소 하나가 확보되어야 실행을 시작한다.

1. compiler-generated stack usage output
2. vendor or qualified static analyzer stack report
3. linker-generated map file from the target build
4. CI or release policy record for `RSRX_ENABLE_STRICT_WARNING_HARDENING`

For the host-toolchain baseline path, the project-provided helper is:

- `sil4/tools/run_stack_memory_evidence.sh`

This helper configures CMake with `RSRX_ENABLE_STACK_MEMORY_EVIDENCE=ON`, builds the representative integration executable, checks that compiler stack-usage files exist, and checks that a representative linker map exists.

## Track A: Stack-Bound Analysis

Required inputs:

1. commit id
2. build configuration and compiler version
3. stack analysis tool/source
4. generated stack output path
5. unresolved call/recursion handling note

Minimum acceptance checks:

1. output is generated by a tool, not manually estimated
2. analyzed object set is identified
3. per-function or per-task bound is present, or the report states why the current host build cannot provide task-level bounds
4. known unresolved calls are listed

Tracker impact:

- close `EVS-009` only after the generated artifact and review reference are available

## Track B: Static Memory Map

Required inputs:

1. commit id
2. build configuration and linker version
3. linker map file or target memory allocation report path
4. executable or target image reference
5. memory-region source, for example linker script or CMake/linker flags

Minimum acceptance checks:

1. map file is tied to the same build configuration as the analyzed executable
2. text/rodata/data/bss and reserved stack/heap regions are identifiable
3. host-only and target-release builds are not mixed without an explicit note
4. any missing target memory layout data is recorded as a gap, not inferred

Tracker impact:

- close `EVS-010` only after the generated artifact and review reference are available

## Track C: Strict-Warning Default-Gate Decision

Required inputs:

1. CI workflow or release process reference
2. selected policy for `RSRX_ENABLE_STRICT_WARNING_HARDENING`
3. exception/deviation path if the policy is conditional
4. review record approving the policy

Allowed decisions:

| Decision | Meaning | Evidence Needed |
| --- | --- | --- |
| `Mandatory` | strict profile must pass for CI/release | workflow or release gate proof |
| `Conditional` | strict profile required for defined branches/releases only | branch/release condition and deviation path |
| `Evidence-only` | strict profile remains a periodic evidence run, not a blocking gate | reviewed rationale and cadence |

Tracker impact:

- close `EVS-011` only after the policy is recorded and reviewed

## Output Package

The first completed package should include:

1. stack-bound report or output reference
2. memory-map report or output reference
3. strict-warning default-gate decision record
4. review record
5. updated `first_actual_vendor_evidence_set_execution_tracker.md`
6. updated `audit_trail_closeout.md`
7. updated `roadmap_status.md`

For a host-toolchain baseline run, the minimum generated package is:

1. `summary.md`
2. `summary.env`
3. `stack_usage_files.txt`
4. `rsrx_session_supervisor_flow_test.map`
5. configure/build logs

Target-release or vendor-qualified runs must still provide their own target/tool metadata.

## Non-Acceptance Rules

Do not close `EVS-009`~`EVS-011` when only the following exists:

1. this runbook
2. `stack_memory_evidence_requirements.md`
3. a manually written estimate
4. a local command transcript without generated artifacts
5. a screenshot without commit id, build config, tool version, and artifact path

## Completion Rule

The track is complete only when actual artifact references and review records replace placeholder text in the tracker.
